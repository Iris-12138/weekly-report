4卡点 · 尝试与反思

🔧 一个真实的卡点：从本地 HTML 到可分享的线上版，"最后一公里"比想象中远

本来以为部署上线是最简单的一步——本地做完的 html 传上去就行。结果这一段反而花了最多时间试错。
卡点
本地做完，部署反而最折腾
指引站功能做完，原以为用 CloudStudio 部署就能完事——结果这只是临时沙箱，链接几天后就会失效；而且每次修改改动都要重新生成新链接。维护成本高、链接不稳定。
➜
尝试
EdgeOne Markers / 其他方案
EdgeOne Markers 接上 MCP 后发现没权限，要走文档申请——对一个实习生做的内部指引站来说太重。又试了其他方式，要么工具门槛高、要么稳定性不够，都不尽如人意。
➜
解决
✓ GitHub Pages 部署上线
最后用 GitHub Pages 部署，完美符合所有需求——链接稳定、改动自动更新、维护成本低。今后任何 BP 都能拿到一个不变的地址访问。
学到的："做完"≠"能用"，"能用"≠"可维护"。交付物不能只考虑"做出来那一刻"，要从一开始就考虑谁来持续维护、链接能不能稳定、后续改动的成本。一个稳定的链接，比花里胡哨的功能更重要。
